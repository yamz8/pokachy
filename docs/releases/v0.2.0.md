# Pokachy v0.2.0

Pokachy v0.2.0 adds self-service profile and account settings to the browser, CLI, and native Omarchy panel.

## Changes

- Let signed-in users change only their own handle, display name, and profile picture; uploaded PNG, JPEG, WebP, and AVIF images are limited to 2 MB.
- Make the panel profile picture open settings and add direct GitHub-linking and verified-email-change actions.
- Require verification of both the current and new inbox before changing an email address.
- Allow explicitly linking a GitHub identity with a different email without replacing the Pokachy account email.
- Open browser settings from the CLI through a five-minute, single-use capability tied to the exact CLI user. Tokens are stored hashed, kept out of URL queries, rejected for a different browser account, and consumed after a successful claim.
- Add `pokachy profile name`, `pokachy profile image`, `pokachy account github`, and `pokachy account email` support while retaining existing profile-handle commands.
- Align CLI, Worker, package, and Omarchy versions to `0.2.0`.

## Verification and rollout

The release requires D1 migrations `0002_profile_settings.sql` and `0003_account_handoffs.sql`, plus the production R2 bucket `pokachy-avatars` bound as `AVATARS`. Create and verify the bucket before deployment, review pending migrations, and run the complete repository verification suite against the exact release revision.

Local tests cover profile ownership, avatar validation, two-step email changes, handoff account binding, expiry, replay resistance, deletion, and retention. Production GitHub consent, real inbox delivery, R2 permissions, browser appearance, and the physical Omarchy desktop remain live rollout checks. Creating the release tag does not deploy production or apply migrations.

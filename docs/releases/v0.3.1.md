# Pokachy v0.3.1

Pokachy v0.3.1 fixes an Omarchy shell crash at startup, stops a signed-out computer from polling the server in the background, and makes adding friends work both ways.

## Changes

- Stop the notification service when this computer is signed out, revoked, or suspended. The daemon exits with status 78, and the systemd unit no longer restarts it every five seconds. `pokachy init` starts the service again.
- Accept a pending friend request when you add the person who sent it. `pokachy friends add` and the Omarchy panel now say whether you are friends or a request was sent.
- Refresh your other open clients, such as the panel and `pokachy tui`, right away when you unblock someone.
- Fix an Omarchy shell crash at startup. The panel loaded profile pictures over HTTPS inside quickshell, and Qt's TLS setup in its image thread could segfault. The CLI now downloads pictures, from GitHub avatars and Pokachy only, without credentials, and the panel shows local files and makes no network requests. Logging out or uninstalling removes the cached pictures.
- Report undeliverable sign-in emails: the Worker now consumes the `pokachy-mail-failed` dead-letter queue, logs an error-level `email_delivery_failed` event without the address or code, and drops the message instead of leaving it queued.
- Include a short error message, with email addresses removed, in `request_failed` logs so unexpected failures can be diagnosed.
- Add database indexes for account, block, report, and friendship lookups, so state syncs, account deletion, and the moderation queue no longer read entire tables.
- Align CLI, Worker, package, and Omarchy versions to `0.3.1`.

## Verification and rollout

The release runs the complete repository verification suite before publishing Linux archives, checksums, and the matching standalone Omarchy plugin. The native end-to-end check confirms that the daemon exits with status 78 when its session is revoked. The restart behavior was also checked against a real systemd user manager.

The production Worker gains a consumer for the existing `pokachy-mail-failed` queue, which needs the Queues Edit permission that `docs/deployment.md` already requires for the deploy token. This release includes one additive migration, `0004_lookup_indexes.sql`, which only creates indexes. Review it in the production deployment workflow before applying it. The reciprocal friend request and unblock refresh take effect when the Worker is deployed. The service fix takes effect when users update with `pokachy update`, which reinstalls the systemd unit.
